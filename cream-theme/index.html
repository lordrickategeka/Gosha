Structured logs that travel well across every runtime.

Loganate is a tiny, opinionated logging library. Compose pipelines, attach typed context, and ship the same logs from your serverless function, your CLI, and your React Native app.

Read the docs npm i loganate
app/server.ts 
import { createLogger, pipeline } from "loganate";

const log = createLogger({
  name: "checkout",
  level: "info",
  sinks: [pipeline.stdout(), pipeline.otlp()],
});

log.info("order placed", {
  userId: user.id,
  amount: 42_95,
  currency: "USD",
});
// → {"lvl":"info","msg":"order placed",...}

Docs Core Structured logging

Structured logging

Logs are easier to search, alert on, and reason about when they are structured. Loganate gives every record a typed payload, a level, a timestamp, and the context of whatever logger produced it.

Overview

A structured log record is a JSON object with a fixed shape. Loganate guarantees four top-level fields — lvl, msg, ts, and ctx — and lets you attach arbitrary typed data alongside them. Records flow from your logger through one or more sinks, transformed by the pipeline you compose.

Every API in this section is also documented in the API reference. If you're already comfortable with the concepts, jump straight there.

Creating a logger

Instantiate a logger with createLogger(). You can declare the shape of its context up front — every subsequent call is type-checked against it.

checkout/logger.ts 
import { createLogger } from "loganate";

type CheckoutCtx = {
  userId: string;
  cartId: string;
};

export const log = createLogger<CheckoutCtx>({
  name: "checkout",
  level: process.env.LOG_LEVEL ?? "info",
});
Naming loggers

The name field is preserved on every record produced by this logger and is what you'll filter on in your log search UI.

Log levels

Loganate ships with five levels. Records at a level below the logger's threshold are filtered before their payload is evaluated — passing an expensive function as a field is safe.

Level Method When to use Stops build?
trace log.trace() Per-call function entry, hot loops no
debug log.debug() Branch decisions during development no
info log.info() Business events worth keeping — orders, signups no
warn log.warn() Recoverable problems — retried request, fallback path no
error log.error() Anything that produced a 5xx or a user-facing failure yes (CI)
Don't log secrets

Even at trace. Use the redaction pipeline to strip sensitive fields before they reach a sink.

Attaching context

Use log.with() to derive a child logger that carries additional context. Children inherit their parent's level and sinks, and merge their context on top.

checkout/handler.ts 
export async function handler(req: Request) {
  const requestLog = log.with({
    requestId: crypto.randomUUID(),
    path: new URL(req.url).pathname,
  });

  requestLog.info("request received");

  try {
    const result = await process(req);
    requestLog.info("request ok", { status: 200 });
    return result;
  } catch (err) {
    requestLog.error("request failed", { err });
    throw err;
  }
}
Async context

Inside Node and Bun, prefer log.flow() to propagate context across await boundaries via AsyncLocalStorage — see the correlation recipe.

Pipelines

A pipeline is an ordered list of transforms and sinks. Records flow through each step in order, can be dropped or duplicated, and ultimately land in one or more sinks.

POST /v3/pipelines Register a new pipeline on the control plane

Composing

Each function in a pipeline receives a record and returns the next one — or null to drop it. The signature mirrors a transducer; chaining is just function composition.

pipeline.ts 
import { pipeline, redact, sample } from "loganate";

const prod = pipeline.compose(
  redact(["password", "token", "ssn"]),
  sample({ trace: 0.01, debug: 0.1 }),
  pipeline.stdout({ format: "json" }),
  pipeline.otlp({ endpoint: process.env.OTLP_URL })
);

Parameter reference

The most-used pipeline transforms and their options:

ParameterTypeRequiredDescription
name string required Identifier for the pipeline. Surfaced on every record.
level Level optional Minimum level to pass through. Defaults to "info" in production, "debug" otherwise.
format "json" | "pretty" | Formatter optional How records are serialized before reaching a sink. Pass a custom Formatter for full control.
sinks Sink[] required One or more destinations. Records are written in parallel; failures are isolated per sink.
onError (err, rec) => void optional Called when a sink throws. Defaults to console.error.
